## 🔴 KRITIS

### K-1 · Semua endpoint API OMS tanpa auth (14 endpoint)
- **Kategori:** Broken Access Control (OWASP A01)
- **Lokasi:** `src/proxy.ts:25` (matcher hanya `'/oms/dashboard/:path*'`), seluruh route: `products/{create,update,delete}`, `combos/{create,update,delete,toggle}`, `promotions/{create,update,delete,toggle}`, `reviews/{reply,visibility}`, `orders/list/route.ts:15`.
- **Masalah:** Guard hanya melindungi *halaman* dashboard; matcher tak mencakup `/api/*`. Tidak ada satu pun route mutasi yang memanggil `verifySessionToken`. Siapa pun tanpa login bisa CRUD produk/combo/promo, memalsukan/menyembunyikan ulasan.
- **Bahaya:** Ambil-alih back-office penuh + (via K-2) dump PII pelanggan.
- **Rekomendasi:** Helper `requireAdmin()` (verifikasi `OMS_SESSION_COOKIE`, 401 bila gagal) di awal semua route OMS; dan/atau perluas `proxy.ts` matcher.

### K-2 · `GET /api/orders/list` bocorkan PII semua pelanggan tanpa auth
- **Kategori:** Sensitive Data Exposure / A01
- **Lokasi:** `src/app/api/orders/list/route.ts:15-18` → `readOrders()` → `rowToOrder` (`src/lib/mock-db/orders.ts:144-172`).
- **Masalah:** Mengembalikan seluruh order lengkap: `customerName`, `customerPhone`, `customerEmail`, alamat penuh, `transactionId`. Tanpa auth.
- **Bahaya:** Dump database pelanggan (data pribadi) dalam satu request anonim.
- **Rekomendasi:** Wajibkan auth admin; batasi field.

### K-3 · Harga & total dipercaya dari client (price manipulation)
- **Kategori:** Business Logic (A04/A08)
- **Lokasi:** `src/app/checkout/page.tsx:195-214` → `orders/create/route.ts:25-45` → `orders.ts:247-263` → `supabase/migrations/20260702120000_create_order_with_items.sql:64-89`.
- **Masalah:** Server cek `price` bertipe number & `totalAmount >= 0` saja; `price_at_purchase` & `jumlah_total` disimpan apa adanya. RPC hanya baca `stock`/`name`, bukan `promo_price`.
- **Bahaya:** Kirim `price:1` → order Rp1, stok tetap terpotong.
- **Rekomendasi:** Ambil ulang `promo_price` dari DB, hitung total server-side, abaikan harga client, enforce `price > 0`.

### K-4 · Sesi OMS gampang dipalsukan — ✅ SELESAI (2026-07-08)
- Diverifikasi ulang 07-10: desain HMAC benar. Login DB-backed (scrypt), cookie HMAC httpOnly, `proxy.ts` verifikasi tanda tangan + expiry. Lihat snapshot 07-08 untuk detail. **Sisa yang kini dilacak terpisah:** fallback secret → **T-1**, kredensial seed → **T-3**.

## 🟠 TINGGI

### T-1 · Secret HMAC fallback hardcoded + token cancel tanpa expiry
- **Lokasi:** `src/lib/oms-auth.ts:21`, `src/lib/order-token.ts:13`; token dipakai `src/app/api/orders/cancel/route.ts:40,72`.
- **Masalah:** `?? 'infarm-dev-...'` — bila env prod kosong, kunci penanda-tangan jadi publik (ada di source) → tempa cookie sesi admin & token pembatalan. Token cancel murni `HMAC(orderId)` tanpa nonce/expiry walau UI klaim "kedaluwarsa".
- **Bahaya:** Ambil-alih sesi admin; pembatalan massal order + `restoreStock`.
- **Rekomendasi:** Fail-fast bila secret prod kosong; rotasi; tambah expiry+nonce di payload token.

### T-2 · Rate limit login lemah — 🟡 SEBAGIAN
- **Lokasi:** `src/app/api/oms/login/route.ts:20-33,52-56`.
- **Masalah:** Limiter in-memory per-instance (reset saat scale) + kunci `x-forwarded-for` yang dikontrol klien (bisa di-spoof).
- **Aman:** pesan error generik (tak bocorkan keberadaan username).
- **Rekomendasi:** Store terpusat + sumber IP tepercaya + lockout per-akun.

### T-3 · Kredensial seed admin lemah & publik (`admin123`) — BARU
- **Lokasi:** `supabase/migrations/20260708120000_init_admin_users.sql:27-34`.
- **Masalah:** `admin@infarm.id` / `admin123` (plaintext di komentar; hash untuk password umum). Setelah K-1 diperbaiki, ini jadi pintu masuk utama. (Juga pemicu peringatan "data breach" Chrome.)
- **Rekomendasi:** Paksa ganti password saat login pertama / seed akun nonaktif; hapus plaintext dari komentar; kebijakan kekuatan password.

## 🟡 SEDANG

### S-1 · HTTP security headers kosong
- **Lokasi:** `next.config.ts`. Absen: CSP, X-Frame-Options, HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy. (Referrer-Policy penting: token HMAC di query cancel bisa bocor via `Referer`.)
- **Rekomendasi:** `async headers()`: `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS (prod), CSP ber-scope.

### S-2 · IDOR `GET /api/orders/get` + invoice tertebak
- **Lokasi:** `src/app/api/orders/get/route.ts:12-35`; invoice `INV-YYYYMMDD-{4 digit}` (`orders.ts:104-108`, ~9000/hari).
- **Masalah:** Tanpa token → kembalikan `customerName` + `items` + `status` untuk sembarang `orderId`. Bisa dienumerasi.
- **Rekomendasi:** Wajibkan token (seperti `orders/cancel`) atau hapus `customerName`; invoice tak-tertebak; rate limit.

### S-3 · Diskon/promo client-side, tak divalidasi server
- **Lokasi:** `src/lib/promo-cart.ts`. Melebur ke K-3 (server percaya total client). Wiring promo→order masih roadmap.
- **Rekomendasi:** Saat wiring dibangun, revalidasi promo/combo dari DB server-side (aktif, belum kedaluwarsa, `min_purchase`).

### S-4 · `reviews/reply` tak terproteksi + panjang/`imageUrls`/review tersembunyi — 🟡 SEBAGIAN
- **Lokasi:** `src/app/api/reviews/{reply,create,list}/route.ts`.
- **Sudah (07-08):** `reviews/create` terikat ke order asli + verifikasi produk + tolak order `Dibatalkan`.
- **Sisa:** `reviews/reply` admin-only (tergantung K-1); batas panjang `authorName`/`comment`; `imageUrls` tak divalidasi (`reviews/create`); `reviews/list` menampilkan review `visible=false` (disembunyikan admin) ke publik.
- **Rekomendasi:** Selesaikan sisa checklist.

### S-5 · `order_items` tanpa migration → RLS tak terverifikasi (schema drift) — BARU
- **Lokasi:** dirujuk `create_order_with_items.sql:88`; tak ada `CREATE TABLE`/`enable row level security` untuk `order_items` di `supabase/migrations/`. Migration `init_orders.sql` masih skema Inggris/JSONB lama vs skema Indonesia live.
- **Masalah:** Skema live diubah manual di Dashboard → posture RLS `order_items` tak bisa dipastikan dari repo. Bila tanpa RLS + Data API auto-expose, `anon` bisa baca `product_id/quantity/price_at_purchase`.
- **Rekomendasi:** Verifikasi di DB live RLS `order_items` ON tanpa policy anon; commit migration yang cocok produksi; matikan "auto-expose new tables".

### S-6 · `products/update` validasi longgar + isi gambar tak divalidasi — BARU
- **Lokasi:** `src/app/api/products/update/route.ts:27-50`; `products/create/route.ts:60`.
- **Masalah:** Update tak pakai `product-validation.ts` (tanpa `SKU_REGEX`, batas panjang, ceiling harga). `images`/`imageUrl` hanya dicek "string" — ukuran/MIME/skema data-URL tak dicek → data kotor / payload base64 raksasa (DoS). Diperparah K-1 (endpoint publik).
- **Rekomendasi:** Pakai `product-validation.ts` di update; validasi ukuran & tipe gambar server-side.

### S-7 · Komponen client mengimpor modul secret `oms-auth.ts` — BARU
- **Lokasi:** `src/app/oms/login/page.tsx:1,13` → `import { sanitizeOmsRedirect } from '@/lib/oms-auth'`.
- **Masalah:** `oms-auth.ts` memuat `SECRET` sesi. `service_role` TIDAK bocor (bukan `NEXT_PUBLIC_`), tapi menarik modul secret ke graph client = anti-pattern rapuh.
- **Rekomendasi:** Pisahkan `sanitizeOmsRedirect` + konstanta redirect ke modul non-secret.

## 🔵 RENDAH

### R-1 · Logging/monitoring minim
Hanya `console.error`; tak ada audit log aksi admin/pembatalan. Rekomendasi: audit log untuk aksi sensitif.

### R-2 · Scan CVE dependency — ✅ DIJALANKAN
`npm audit`: **3 moderate, 0 high/critical**. Semua turunan advisory `postcss` (XSS via unescaped `</style>`) lewat `next`; **fix belum tersedia** upstream (range `next` ≤ 16.3.0-canary). Aksi: pantau rilis Next; tak ada `npm audit fix` yang aman sekarang.

### R-3 · Tak ada proteksi CSRF di API routes
Cookie sesi `SameSite=Lax` + ekspektasi JSON memberi mitigasi parsial. Jadi risiko utama **setelah** K-1 diperbaiki. Rekomendasi: cek `Origin` allow-list / double-submit token; pertimbangkan `SameSite=Strict` untuk cookie admin.

### R-4 · Proxy alamat Mengantar tanpa rate limit
`src/app/api/mengantar/address/search/route.ts` — host hardcoded + `encodeURIComponent(keyword)` → **bukan SSRF**, tapi bisa jadi relay abuse. Rekomendasi: rate limit + batas panjang keyword.

### R-5 · `/dev/email-preview` aktif di prod + template email `{{ }}` tak di-escape — BARU
- **Lokasi:** `src/app/dev/email-preview/route.ts` (tanpa gate `NODE_ENV`); `src/emails/order-confirmation.html`.
- **Masalah:** Preview aktif di produksi (bocor markup template, low). Substitusi placeholder `split/join` tanpa HTML-escape — aman sekarang (data contoh), **jadi Sedang saat pengiriman email produksi di-wire**.
- **Rekomendasi:** Gate 404 di produksi; HTML-escape semua placeholder scalar sebelum kirim email nyata.

## ✅ Yang sudah benar (terverifikasi 2026-07-10)
- **SQL injection: tidak ada** — semua query builder terparametrisasi; RPC plpgsql `security definer` + `set search_path`, tanpa dynamic SQL/`format()`.
- **XSS klasik: tidak ada** — nol `dangerouslySetInnerHTML`/`innerHTML`; teks user via JSX (auto-escape).
- **`service_role` tak bocor** ke bundle client (import graph bersih); `NEXT_PUBLIC_*` semua layak publik; `.env*` di-`.gitignore`.
- **Stok race-safe** — RPC `SELECT … FOR UPDATE` + rollback bila kurang.
- **RLS tabel ber-migration benar** — `products`/`reviews` read publik terbatas; `orders`/`promotions`/`combos`/`admin_users` terkunci tanpa policy anon.
- **`orders/cancel`** — token HMAC di GET & PATCH, validasi status server-side, respons tanpa PII.
- **Password admin** — scrypt + salt + `timingSafeEqual`; login error generik; cookie flags aman.
